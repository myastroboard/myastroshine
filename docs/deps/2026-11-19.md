### FastAPI 0.164 / 0.165

Both releases add opt-in limits. With no setting, the request body stays unlimited, so large
FITS/RAW uploads behave as before. The new form parser defaults (1000 files, 1000 fields, 1 MiB
per text field) are far above our use: stack uploads send at most `UPLOAD_BATCH_MAX_FILES = 20`
files per request (`backend/app/constants.py`), and the only text field is `start_index`.
FastAPI requires `starlette>=1.6.0`. The suite was run with both Starlette 1.8.0 (local) and
1.10.0 (what a fresh CI or Docker install gets).

### OpenCV 5.1

Release notes: https://github.com/opencv/opencv/wiki/OpenCV-Change-Logs#version510. The
behaviour changes compared with our `cv2` calls:

- `remap` INTER_NEAREST rounding with fixed-point maps: we only use INTER_LINEAR / LANCZOS4 with
  float maps (`star_match.py`, `integration.py`). Not affected.
- int64 NumPy arrays now map to CV_64S instead of being truncated, and saturating 32-bit
  integer arithmetic: no int64 or int32 array is passed to `cv2` in `backend/app`.
- `bitwise_not` / `inRange` on CV_Bool: our `inRange` call (`depth_map.py`) uses float input.
- TIFF falls back to LZW when the requested codec is missing: we pass no TIFF compression
  parameter.
- DNN classic engine and `readNetFromTensorflow` removed: `cv2.dnn` is not used.

The golden-image regression tests (`tests/regression/`) pass without updating the references.

## 5. Points to watch

- **Local test environment (Windows, not a dependency issue)**: when Node starts in a directory
  written with a lowercase drive letter (`d:\Code\...`, the form the VSCode terminal sometimes
  uses), vitest loads twice and every suite fails with
  `TypeError: Cannot read properties of undefined (reading 'config')`. This happens with
  jest-dom 7.0.1 as well as 8.0.0. From `D:\Code\...` everything passes. CI (Linux) is not
  affected.
- **Local Python runtime**: the `.venv` runs Python 3.14.8, while `requires-python` and
  CI/Docker use 3.15. Everything passes on 3.14, but the local venv does not match CI. The
  runtime was not changed.
- **Fresh releases**: jest-dom 8.0.0 and vitest 5.1.1 came out within the last 24 hours, and
  FastAPI 0.165.0 the day before.
- **Manual checks suggested**: process a real stack and a single Milky Way photo end to end
  (the OpenCV bump changes numeric code paths that the synthetic golden images cover only in
  part). Before merging, a real large upload (several hundred MB of FITS) would confirm that no
  413 or 400 error appears.
- **Pre-existing warnings**: Vite's chunk-size warning on `npm run build` and 9 pytest warnings,
  all present before the update.
- **Majors to plan**: TypeScript 7, blocked upstream by typescript-eslint (see DEPENDENCY_PINS.md).
